# Go Wails IPC Bridge (Creative-ink)

You are an expert Go developer specialised in Wails v2 backends. Goal: secure, non-blocking,
cleanly separated backend code.

Read first: `CLAUDE.md` (rules, status) and `docs/MAP.md` §2 (layers) and §3 (IPC contract).
Those files win over this skill if they disagree.

## Layout (verify before relying on it)

- `creative-ink/main.go`: `wails.Run`, `Bind: []any{app}`, `AssetServer.Middleware`.
- `creative-ink/app.go`: `App` facade (`ctx`, `files`, `docPath`, `compiles`, injectable `emit`), event
  name constants and result types (`SaveResult`). Tests in `app_test.go` use a fake emitter.
- `creative-ink/preview.go`: HTTP middleware serving `/__preview/document.pdf`.
- `creative-ink/internal/{core,compiler,system}`: business logic, **no Wails imports**.
- Generated JS bindings: `frontend/wailsjs/` (regenerated by `wails dev` / `wails build`; never edit).

## When to use

- Writing backend logic in Go for this Wails application.
- Creating or changing IPC methods in `app.go` or Wails events.
- File system operations or orchestration of external processes (also see `latex-toolchain-orchestrator`).

## Principles & architecture rules

1. **Single entry point.** `App` in `app.go` is the ONLY struct bound to the frontend. Do not bind
   internal structs. Exported methods on `App` become JS functions: keep that surface small and
   intentional, and unexport helpers (`pdfPath()`, not `PDFPath()`).
2. **Frontend isolation.** The frontend never touches the disk or launches processes. Go is the
   source of truth for the filesystem. Never accept arbitrary paths from JS without validating them
   against an allowed root. Prefer IDs or paths relative to the open workspace.
3. **Layering.** `internal/*` must not import `github.com/wailsapp/wails`. When internal code must
   notify progress, inject a callback or a small interface from `App`
   (e.g. `type Notifier func(event string, payload any)`). Only `app.go` calls `runtime.EventsEmit`.
4. **Non-blocking execution.** Long-running work (compilation, scans, downloads) MUST NOT block the
   IPC return.
   - Bad: the frontend waits up to 60 s for a binding that compiles.
   - Good: `SaveContent()` saves and returns at once (it never compiles). Compiling is a separate
     request, `RequestCompile(trigger)` (`"auto"` from the idle timer, rejected while the
     `compile.auto` setting is off; `"manual"` from ⌘S), which queues a background job that emits
     `compile:started` and `compile:finished` (with a result payload).
   - Coalesce bursts: if a request arrives while a job runs, mark it dirty and run **one** more
     job with the latest state when the current one ends. Do not queue N jobs.
   - Reference implementation: `internal/compiler/scheduler.go` (`Scheduler`: single worker,
     coalescing, bounded cancellation of young automatic runs, panic recovery, `Close` with
     cancellation) wired in `app.go` through `Hooks`.
   - Long output (terminal, manual builds): stream it to disk (`core.OutputSpool`) and emit
     throttled progress events; let the UI pull the full text on demand (`ReadTerminalOutput`).
     Never hold minutes of output in memory or return it in one IPC message.
   - Settings: read and write them only through the config service (`internal/config`,
     `App.GetConfig`/`SetConfig`, event `config:changed`), never by opening `settings.json` or
     `.creative-ink-meta` directly.
   - Changing a binding or event alters the IPC contract: update `docs/MAP.md` §3 and the Svelte
     side in the same change.
5. **Clean error handling.**
   - The operation itself failed (cannot write the file): return `error` → the JS promise rejects.
   - Expected domain outcomes (compilation failed, tool missing, partial hardware probe): return a
     result struct with `json` tags (`{ success: false, logs: "…" }`, `warnings: []`). Never panic.
   - Wrap errors with context: `fmt.Errorf("write %q: %w", path, err)`. Use sentinel errors for
     cases the caller checks (`errors.Is`).
6. **Arbitrary execution is fenced.** `RunTerminalCommand` (integrated terminal) runs shell commands by
   design. Never add another binding that executes processes from JS-provided strings, and never let
   the UI build terminal commands from documents, logs or file names.
7. **Contract discipline.** Every new binding, event or HTTP route goes into the table in
   `docs/MAP.md` §3 in the same change. Event names follow `domain:action` (`compile:finished`),
   and payloads are structs with camelCase `json` tags.

## Gotchas

- **`runtime.EventsEmit` with a nil or non-Wails context calls `log.Fatalf` and kills the process.**
  Always emit through `App.emit` (no-op before `startup`), never call the runtime from tests.
- **Context matters.** Keep the Wails `context.Context` saved in `startup` (`a.ctx`); it is required
  for `runtime.EventsEmit` and dialogs. Do not use it before `startup` has run. For background jobs,
  derive a cancellable context and cancel it in `OnShutdown` so latexmk does not outlive the app.
- **Data races.** Wails runs every bound call on its own goroutine, and background jobs add more. Any
  state shared between them (current document path, "compile pending" flags, caches) needs a
  `sync.Mutex`, an atomic or a single owner goroutine with channels. Verify with `go test -race ./...`.
- **Panics in goroutines crash the whole app.** Wails does not recover them. Wrap background job
  bodies in a `defer func() { if r := recover(); r != nil { /* emit error event */ } }()`.
- **Event listeners on the JS side.** `EventsOn` returns an unsubscribe function: the Svelte
  component must call it on destroy, or listeners pile up with every hot reload.
- **Bindings change shape.** After changing a method signature, tell the user to restart `wails dev`
  so `wailsjs/go/main/App.{js,d.ts}` and `models.ts` are regenerated.
- **Middleware, not Handler.** Dynamic HTTP assets go through `AssetServer.Middleware`; in `wails dev`
  the `Handler` is only reached on a Vite 404 (see `preview.go`).
- **Project rules.** You must not run `wails dev/build`, `go get`, `go mod tidy` or `go run`.
  If a dependency is needed, stop and give the user the exact command.
